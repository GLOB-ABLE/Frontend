## 1. 배경과 문제 정의

### 1.1 배경

국내 대학을 졸업한 외국인 유학생은 매년 늘고 있지만, 졸업 후 국내 취업으로 이어지는 비율은 낮습니다. 동시에 지역 중소 수출기업은 외국어·현지 시장 이해를 갖춘 인력을 필요로 하면서도 외국인 채용에 이르지 못합니다. 학생과 기업 모두 의사가 있는데도 연결되지 않는다는 것이 이 제품의 출발점입니다.

1차 예선 서비스(글로버블)는 개인이 자신에게 맞는 진로를 발견하도록 돕는 개인화 경험이 강점이었습니다. 본 제품은 그 경험을 유지하되, 채용이 성사되지 않는 원인을 학생 개인의 부족으로만 보지 않고 학생·기업·대학·전문가가 함께 해결하는 구조로 확장합니다.

### 1.2 문제 진술

현재 시장에는 세 종류의 정보 비대칭이 동시에 존재합니다.

| 주체 | 겪는 문제                                                                                        | 현재의 대응                                      | 왜 실패하는가                                                              |
| ---- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------- |
| 학생 | 어떤 직무에 지원할 수 있는지, 무엇이 부족한지 모른 채 지원과 탈락만 반복한다                     | 일반 채용 플랫폼에 지원, 커뮤니티·학원 정보 의존 | 탈락 사유 피드백이 없어 다음 시도가 개선되지 않는다                        |
| 기업 | 요구 직무에 맞는 유학생을 찾기 어렵고, 제시 가능한 조건이 지원자 기대와 맞는지 사전에 알 수 없다 | 지인 소개, 일반 공고 게시                        | 공고가 모호해 지원자가 스스로 판단할 수 없고, 외국인 채용 절차 부담이 크다 |
| 대학 | 담당 유학생 규모 대비 인력이 부족해 개입이 필요한 학생을 선별하지 못한다                         | 개별 상담, 엑셀 관리                             | 위험 신호를 사후에야 확인하고, 성과 데이터가 수작업으로 흩어진다           |

> **핵심 문제 진술**
>
> 채용이 성사되지 않는 이유는 대부분 "학생의 역량 부족" 하나가 아니라, 학생 역량 · 증빙 부재 · 공고 정보 부족 · 기업 준비 미비 · 체류 절차 정보 누락이 섞여 있다. 그런데 현재 어떤 서비스도 이 원인을 분해해서 "누가 무엇을 해야 하는지" 알려주지 않는다.

### 1.3 제품 가설

1. 채용을 막는 요인을 5개 유형으로 분해하고 각 요인의 책임 주체를 명시하면, 학생과 기업이 각자 실행 가능한 다음 행동을 갖게 된다.
2. 모호한 공고 표현을 실제 업무 행동으로 번역하면, 학생은 스스로 적합 여부를 판단할 수 있고 기업은 검증 가능한 기준을 얻는다.
3. 학력·어학 점수 대신 직무 기반 실무미션 결과를 제시하면, 기업이 외국인 지원자를 판단할 근거가 생긴다.
4. 체류자격 정보를 "발급 가능 여부 판정"이 아니라 "준비 누락 점검"으로 다루면, 법적 리스크 없이 실질적 도움을 줄 수 있다.

## 2. 목표와 성공지표

### 2.1 제품 목표

| ID  | 목표                              | 설명                                                                                              |
| --- | --------------------------------- | ------------------------------------------------------------------------------------------------- |
| G1  | 지원 이전에 판단 가능하게 만든다  | 학생이 지원 전에 이 공고에서 무엇이 충족되고 무엇이 부족한지 근거와 함께 확인할 수 있다           |
| G2  | 책임을 분해한다                   | 채용 장애요인을 학생·증빙·공고·기업준비·체류정보로 나누고 각각의 해결 주체와 최소 행동을 제시한다 |
| G3  | 역량을 증명 가능하게 만든다       | 실무미션 결과로 학력·어학 점수 밖의 직무 수행 능력을 기업에 전달한다                              |
| G4  | 법적·윤리적으로 안전하게 운영한다 | 취업활동 자격 없는 사용자에게 알선하지 않고, AI가 채용·비자 결과를 확정하지 않는다                |

## 6. 신규 정의 A — 체류자격 게이트

### 6.1 왜 필요한가

상위 IA·RFP 정의서는 체류 관련 기능을 "체류정보 사전점검"이라는 추상 항목으로만 다루고 있으며, D-2·D-10·E-7 등 체류자격 유형 구분이 존재하지 않습니다. 그러나 이 서비스에서 사용자의 체류자격은 부가 정보가 아니라 서비스 제공 가능 여부 자체를 결정하는 선행 조건입니다.

> ⚠️ **법적 근거**
>
> **출입국관리법 제18조 제3항** — 누구든지 취업활동을 할 수 있는 체류자격을 가지지 아니한 사람을 고용하여서는 아니 된다.
>
> **같은 조 제4항** — 누구든지 취업활동을 할 수 있는 체류자격을 가지지 아니한 사람의 고용을 알선하거나 권유하여서는 아니 된다.
>
> **같은 법 제94조** — 위반 시 3년 이하의 징역 또는 3천만원 이하의 벌금.
>
> 즉 재학 중인 D-2 유학생에게 정규직 채용 공고를 추천하고 지원을 유도하는 행위는 알선에 해당할 소지가 있습니다. 이는 서비스 운영 주체의 형사 리스크이므로, 기능이 아니라 인수 조건으로 다룹니다.

한편 상위 정의서의 STU-035(체류정보 사전점검)는 공고 지원 이후 단계에 배치되어 있습니다. 이는 순서가 반대입니다. 자격 확인은 공고를 보여주기 전에 이루어져야 합니다.

| 구분           | 기존 IA                  | 본 PRD                                      |

| 확인 시점      | 지원 준비 단계 (STU-035) | 회원가입 직후 (VG-001)                      |
| 목적           | 서류 누락 점검           | 서비스 제공 가능 여부 판별 + 서류 누락 점검 |

> 차단 화면은 오류처럼 보이지 않아야 합니다. "왜 지금은 이용할 수 없는지, 어떤 조건이 갖춰지면 이용할 수 있는지, 지금 할 수 있는 것은 무엇인지"를 함께 안내합니다.

### 6.4 D-10 점수 사전점검

D-10(구직) 체류자격은 학사 이상 학위 소지만으로 부여되지 않고 점수제 심사를 거칩니다. 학생 페르소나가 가장 먼저 마주치는 관문이므로 서비스의 첫 가치 제공 지점으로 삼습니다.

| 구분      | 항목                                                                    | 비고                                    |
| --------- | ----------------------------------------------------------------------- | --------------------------------------- |
| 기본항목  | 연령, 최종학력                                                          | 기본항목 합계가 일정 기준 이상이어야 함 |
| 선택항목  | 최근 근무경력, 국내 유학경력, 국내 연수·교육경력, 한국어능력            | TOPIK 급수가 반영되는 영역              |
| 가점항목  | 기관장 추천, 글로벌기업 경력, 우수대학 졸업, 이공계 학위, 고소득 전문직 | 해당자에 한함                           |
| 합격 구조 | 기본항목 최소 기준 충족 + 총점 기준 이상                                | 총점·기준은 공식 배점표 기준            |

> ⚠️ **배점 하드코딩 금지**
>
> 배점표는 개정됩니다. 실제로 2025년 10월 개정으로 D-10 최대 체류기간이 2년에서 3년으로 연장되고 갱신 단위가 변경되었습니다.
>
> 따라서 배점 수치는 코드에 상수로 넣지 않고, 운영자 콘솔(ADM 체류규칙 관리)에서 공식 출처 URL · 시행일 · 버전과 함께 관리되는 규칙 데이터로 다룹니다. 화면에는 항상 "적용 기준일"과 "출처"를 표시하고, 기준일이 오래되면 결과 대신 경고를 노출합니다. 이는 제품 원칙 PR-5와 상위 요구사항 NFR-019(데이터 품질·계보) 및 상위 정의서 판단 원칙 5를 따르는 것입니다.

**출력 형태**

- 예상 점수 구간과 항목별 기여도 — 확정 점수가 아니라 입력 기준 추정임을 명시
- 기준 미달 시 부족 점수와, 점수를 올릴 수 있는 합법적 행동 목록 (예: TOPIK 급수 상향, 국내 연수 이수)
- 각 행동을 MVP-05 최소 해결경로에 담당·기한과 함께 등록
- 불확실하거나 복잡한 사례는 발급 가능 여부를 말하지 않고 전문가 검토(MVP-11)로 전환

## 7. 신규 정의 B — 국적 요구의 언어·시장 요건 치환

### 7.1 문제

기업 페르소나는 "베트남 사람을 뽑고 싶다"고 표현합니다. 이 요구를 국적 필드로 그대로 받으면 두 가지 문제가 발생합니다.

- 상위 요구사항 **NFR-014(공정성)**와 정면으로 충돌합니다. 해당 요구사항은 "국적·성별 등 보호속성을 부당한 추천·정렬·탈락 기준으로 사용하지 않아야 한다"고 규정합니다.
- 국적은 기업이 실제로 필요로 하는 것의 **대리변수**일 뿐입니다. 진짜 요구는 베트남어 업무 소통, 베트남 시장·상관습 이해, 현지 거래처 대응입니다. 국적으로 필터링하면 요구를 충족하는 다른 후보를 놓치고, 요구를 충족하지 못하는 동일 국적자를 추천하게 됩니다.

> ✅ **설계 판단**
>
> 국적을 금지 필드로 두는 것은 규제 대응이 아니라 매칭 품질 개선입니다. 국적을 언어·시장 요건으로 치환하면 검증 가능한 조건이 되고, 그 조건은 그대로 학생 측 4상태 갭 분석 항목과 실무미션 과제로 이어집니다.

### 7.2 치환 규칙

| 기업 원문 표현               | 치환 대상 필드                                                              | 매칭 사용 | 학생 화면 표시                                 |
| ---------------------------- | --------------------------------------------------------------------------- | --------- | ---------------------------------------------- |
| "베트남 사람", "베트남 국적" | `job_language_req = vi`<br>`target_market = VN`                             | 사용      | "베트남어로 거래처 응대"<br>"베트남 수출 업무" |

| "한국어 능통"                | `korean_work_behavior = [전화응대, 회의참여, 보고서작성, 고객응대]` 중 선택 | 사용      | 선택된 업무행동 단위로 표시                    |

> **국적값 저장 정책**
>
> 학생의 국적은 회원 정보로 보유하되 (통계·비식별 집계 목적), 공고 요건 필드로는 저장하지 않고 추천·정렬·필터 파이프라인에 전달하지 않습니다. 대학 화면(UNI-006)에서의 국적 검색은 동의 범위 내 학생 관리 목적으로만 허용하며, 채용 매칭에는 연결하지 않습니다.

### 7.3 EMP-009(AI 직무 통역) 확장 스펙

기업이 공고 작성 중 국적·성별·연령 표현을 입력하면 저장 전에 인터셉트하고 치환을 제안합니다.

**검증 기준** — 국적·성별·연령 표현 테스트셋 20종 입력 시 치환 제안 발생률 100%, 원문 보호속성 값이 매칭 파이프라인에 전달되는 사례 0건.

## 9. 기능 상세 스펙

### MVP-00. 체류자격 게이트 · D-10 점수 사전점검 (신규)

|               |                                |                   |                                                |
| ------------- | ------------------------------ | ----------------- | ---------------------------------------------- |

- **핵심 규칙** — 시스템은 체류자격을 판정하지 않고 분류만 한다. 발급 가능·불가를 단정하지 않는다. VG-A가 아닌 사용자에게는 서버 레벨(RLS + API 검사)에서 공고 추천·지원·후보 노출을 차단한다.
- **완료 기준(DoD)** — VG-A 아닌 계정으로 추천·지원 API 직접 호출 시 모두 거부된다. 점수 결과 화면에 적용 기준일과 출처가 100% 표시되며, 기준일이 설정 임계값을 넘으면 결과 대신 경고가 노출된다.

### MVP-01. 프로필·이력서 AI 구조화

|               |                   |                   |                                  |
| ------------- | ----------------- | ----------------- | -------------------------------- |
| **우선순위**  | P0                | **사용자**        | 학생                             |

- **완료 기준(DoD)** — 샘플 이력서 10건에서 학력·기간·직무 필수 필드 정확도 85% 이상. 모든 추출 항목에서 원문 위치로 역추적 가능.

### MVP-02. 취업 나침반 진단

| **우선순위**  | P0                | **사용자**        | 운영자                           |
| **연계 화면** | ADM-013 ~ ADM-020 | **연계 요구사항** | FR-ADM-004 ~ FR-ADM-007, NFR-013 |

- **목적** — 데모에서 사용하는 규칙·프롬프트·출처를 버전으로 추적 가능하게 만든다.
- **입력** — 체류 규칙셋, 직무·역량 표준코드, 프롬프트·출력 스키마, 지식원 목록, 시드 데이터
- **처리** — 규칙·프롬프트·코드에 버전과 시행일을 부여하고 배포·롤백 이력을 남긴다. AI 호출은 마스킹된 입출력·모델·지연·비용·오류코드로 로깅한다.
- **출력** — 버전 관리 화면, AI 호출 로그, 시드 데이터 관리, 기업·담당자 인증 승인 처리
- **핵심 규칙** — 체류 규칙 배포는 공식 출처와 시행일이 있어야 하며 이중 승인 후 반영한다. 로그에 평문 민감정보가 남지 않는다.
- **완료 기준(DoD)** — 데모에서 제시된 모든 판정 결과가 규칙 버전·프롬프트 버전으로 역추적된다. 로그 민감정보 유출 테스트 0건.

## 10. 핵심 도메인 규칙

### 10.1 4상태 갭 판정

요건별 판정은 확률이나 점수가 아니라 아래 4개 상태로만 표현합니다. 전 화면에서 상태명·정의·색상·도움말이 동일해야 합니다.

| 상태          | 판정 조건                                          | 예시                                               | 다음 행동                            |
| ------------- | -------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| **충족**      | 요건에 대응하는 구조화 데이터가 있고 증빙이 유효함 | 요건 TOPIK 4급 / 학생 TOPIK 4급 증빙 보유          | 없음                                 |
| **미충족**    | 대응 데이터는 있으나 기준에 미달함                 | 요건 TOPIK 5급 / 학생 4급                          | 학생 보완 행동 생성                  |
| **확인 필요** | 데이터 없음, 증빙 없음, 또는 요건 자체가 모호함    | "커뮤니케이션 능력 우수" / 경험은 있으나 증빙 없음 | 학생 증빙 제출 또는 기업 공고 구체화 |
| **해당 없음** | 해당 요건이 이 지원자에게 적용되지 않음            | 병역 요건                                          | 없음                                 |

> ⚠️ **가장 중요한 판정 규칙**
>
> 유사한 표현이 있다고 해서 충족으로 확정하지 않습니다. 증빙이 없으면 항상 확인 필요입니다. 이 규칙이 무너지면 학생에게 잘못된 기대를 주고 기업의 신뢰를 잃습니다. AI가 "충족"을 제안하더라도 증빙 레코드가 없으면 규칙 엔진이 확인 필요로 덮어씁니다.

### 10.2 장애요인 유형과 책임 주체

| 유형             | 1차 책임         | 예시                                 | 해결 행동 · 연계 화면           |
| ---------------- | ---------------- | ------------------------------------ | ------------------------------- |
| 학생 역량        | 학생             | 무역 실무 경험 없음                  | 실무미션 수행 (STU-031)         |
| 증빙 부재        | 학생             | 경험은 있으나 증명할 문서 없음       | 문서 업로드·자격 취득 (STU-016) |
| 공고 정보 부족   | 기업             | 급여 범위·상세 업무 미기재           | 공고 보완 (EMP-008)             |
| 기업 준비 미비   | 기업             | 외국인 담당자·온보딩 절차 없음       | 준비도 체크 완료 (EMP-005)      |
| 체류정보 누락    | 학생 · 기업 공동 | 기업 측 확인정보 또는 학생 서류 누락 | 체류 사전점검 (STU-035)         |
| 전문가 판단 필요 | 전문가           | 규칙으로 결정되지 않는 복합 사례     | 전문가 검토 요청 (STU-036)      |

### 10.3 상태 전이

| 대상        | 상태 흐름                                                              | 전이 권한                    |
| ----------- | ---------------------------------------------------------------------- | ---------------------------- |
| 지원        | 관심 → 지원 → 서류검토 → 미션 → 면접 → 오퍼 → 채용 / 종료              | 기업 담당자 (학생은 철회만)  |
| 미션        | 생성 → 사람 승인 → 배정 → 제출 → AI 초안평가 → 사람 확정 → 이의 → 종결 | 기업·대학 평가자             |
| 전문가 사례 | 요청 → 동의확인 → 배정 → 보완요청 → 검토 → 완료 / 재검토               | 전문가 (배정은 운영자)       |
| 게이트      | VG-D → VG-C / VG-B / VG-A (증빙·학적 변경 시 재평가)                   | 규칙 엔진 (사용자 입력 기반) |

AI는 어떤 상태 전이도 단독으로 수행하지 않습니다(PR-3). 모든 전이는 권한자 확정 + 감사로그 기록을 동반합니다.

## 11. 데이터 모델 개요

상세 스키마는 별도 산출물이며, 여기서는 주요 엔터티와 이 제품 고유의 제약만 정의합니다.

| 영역        | 주요 엔터티                                                                                          | 고유 제약                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 회원·자격   | `user`, `role`, `visa_status`, `gate_state`, `consent_ledger`                                        | `gate_state`는 규칙 엔진 산출값이며 사용자가 직접 수정할 수 없다                                            |
| 학생        | `student_profile`, `education`, `experience`, `skill`, `language_behavior`, `credential`, `document` | 모든 역량 항목은 `credential`(증빙)과 연결 가능해야 하며, 연결 없는 항목은 갭 판정에서 확인 필요로 처리된다 |
| 기업·공고   | `company`, `company_readiness`, `job_posting`, `job_requirement`, `posting_version`                  | `job_requirement`에 국적·성별·연령 필드를 두지 않는다. 대신 `language_req`, `target_market`을 사용한다      |
| 판정        | `gap_result`, `blocker`, `scenario`, `action_plan`                                                   | 모든 판정 레코드는 `rule_version`, `model_version`, `evidence_ref`를 필수로 가진다                          |
| 미션·평가   | `mission`, `rubric`, `submission`, `ai_evaluation`, `human_evaluation`, `appeal`                     | `ai_evaluation`은 `human_evaluation` 없이 확정 상태가 될 수 없다                                            |
| 체류·전문가 | `residence_check`, `required_document`, `expert_case`, `expert_opinion`                              | `expert_case` 생성은 `consent_ledger`의 유효 동의 레코드를 전제로 한다                                      |
| 운영        | `rule_set`, `prompt_version`, `knowledge_source`, `ai_call_log`, `audit_log`                         | `rule_set`과 `knowledge_source`는 `official_url`, `effective_date`를 필수로 가진다                          |

**이력·재현성**

- 프로필·공고·근로조건·규칙·프롬프트·평가·동의의 변경 전후와 효력 시점을 보존한다.
- 과거 시점 기준으로 동일한 판정 결과를 재현할 수 있어야 한다. 분쟁·이의제기 대응의 전제 조건이다.
- 성과 분석은 가명·집계 데이터를 사용하며, 최소 집계 기준 미만의 셀은 마스킹 또는 통합 처리한다.

## 12. AI 정책

### 12.1 출력 구조

- 모든 LLM 출력은 버전이 부여된 JSON 스키마로 검증한다.
- 필수 필드 누락, 허용값 위반, 길이 초과 시 재처리하거나 안전 실패하며, 비정상 데이터를 업무 DB에 확정 저장하지 않는다.
- 추출·판정·추천에 사용한 원문 위치, 출처 URL, 수집일, 기준일, 규칙·모델 버전을 함께 저장한다.

### 12.2 금지 출력

아래 표현은 어떤 기능에서도 생성되어서는 안 되며, 출력 필터와 테스트셋으로 검증합니다.

| 금지 출력                                     | 대신 사용하는 표현                                                   |
| --------------------------------------------- | -------------------------------------------------------------------- |
| "합격 확률 72%", "채용 가능성 높음"           | 진행 가능 / 조건 보완 필요 / 추가 정보 필요 / 전문가 검토 필요       |
| "비자 발급이 가능합니다", "발급이 어렵습니다" | "현재 입력 기준으로 확인이 필요한 항목이 N개 있습니다" + 전문가 연결 |
| "베트남 국적이라 이 공고에 적합합니다"        | "베트남어 업무 소통 요건을 충족합니다"                               |

## 15. 해커톤 데모 계획

학생 → 기업 → 학생으로 화면을 전환하며 세 주체가 하나의 채용 건을 함께 해결하는 장면을 10분 안에 보여줍니다.

| #   | 장면                 | 보여줄 것                                                                                 | 시간  |
| --- | -------------------- | ----------------------------------------------------------------------------------------- | ----- |
| 1   | 온보딩과 자격 게이트 | Linh가 체류정보 입력 → VG-A 통과. D-10 점수 사전점검 결과와 부족분, 적용 기준일·출처 표시 | 1분   |
| 2   | 프로필 구조화        | 이력서 업로드 → AI 추출 → 원문 근거 하이라이트 → 학생 수정·확정                           | 1.5분 |
| 3   | 나침반 진단          | 희망조건·역량·한국어 업무행동 입력 → 추천 직무 3개와 근거                                 | 1분   |
| 4   | 공고 해석과 갭       | "한국어 능통"이 전화 응대·회의 참여로 번역되는 장면. 요건별 4상태 판정과 근거             | 2분   |
| 5   | 장애요인 분해        | 학생 책임 3건 / 기업 책임 2건으로 분해되는 화면. 이 제품의 핵심 주장                      | 1.5분 |
| 6   | 기업 화면 전환       | 공고 작성 중 "베트남 사람" 입력 → 즉시 치환 제안 → 언어·시장 요건으로 구조화              | 1분   |
| 7   | 쌍방 시뮬레이션      | 학생 보완 + 기업 보완을 동시에 가정 → 상태 재계산 → 최소 해결경로 생성                    | 1.5분 |
| 8   | 실무미션             | 미션 생성 → 학생 제출 → AI 초안 평가 → 기업 담당자 확정                                   | 0.5분 |
