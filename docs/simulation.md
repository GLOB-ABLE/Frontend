## 1. 무엇을 만드는가

한국 직장의 첫 손님 응대를 5단계로 연습하는 시뮬레이션입니다. 업무 지시를 듣고, 뜻을 고르고, 말하고, 웹캠 앞에서 행동까지 해봅니다.

| 단계 | 내용                       | 입력        |
| ---- | -------------------------- | ----------- |
| 1    | 업무 지시 듣기             | 읽기        |
| 2    | 지시 의미 확인 + 말하기    | 선택 + 음성 |
| 3    | 행동 미션 (명함 양손 전달) | **웹캠**    |
| 4    | 돌발 상황 질문하기         | 텍스트/음성 |
| 5    | 종합 피드백                | —           |

## 2. 원본에서 바꾸는 것

프로토타입을 그대로 옮기지 않습니다. 세 가지를 고칩니다.

### 2.1 점수 → 4상태

프로토타입 마지막 화면은 `92 / 100`과 항목별 점수를 씁니다. 디자인 시스템 2장 금지 패턴 1번(확률·점수·게이지)에 걸립니다.

점수는 왜 90이고 92인지 설명할 수 없습니다. 웹캠 판정은 실제로는 "2초 유지했나 / 못 했나"뿐이라 92라는 숫자가 나올 근거가 없습니다.

| 원본                    | 바꾼 뒤                                               |
| ----------------------- | ----------------------------------------------------- |
| `92 / 100`              | `4개 중 3개를 해냈어요`                               |
| `지시 이해 100점`       | `✓ 충족` · B를 정확히 골랐어요                        |
| `의미 카드 발화 94점`   | `✓ 충족` · 두 가지 행동을 모두 말했어요               |
| `악수 동작 수행 92점`   | `? 확인 필요` · 2초 유지 중 1.4초에서 손이 벌어졌어요 |
| `높임말·질문 표현 90점` | `✓ 충족` · "여쭤봐도 될까요"를 썼어요                 |

기존 `StatusBadge` · `RequirementBar` · `EvidenceChipRow`를 그대로 재사용합니다.

### 2.2 악수 → 명함 양손 전달

원본 3단계는 **악수**입니다. 가이드가 "오른손을 앞으로 내밀기 / 왼손으로 오른쪽 손목 받치기"입니다.

그런데 `02_hand_test`가 검증하는 건 **양손 전달**입니다.

```js
results.multiHandLandmarks.length === 2        // 양손이 다 보여야 함
handLabels.includes('Left') && ...('Right')     // 한 사람의 왼손+오른손
wristDistance <= 0.38                           // 두 손목이 가까이
avgWristY >= 0.35 && <= 0.95                    // 가슴/배 높이
2000ms 유지                                     // 2초
```

악수 자세는 한 손만 뻗으므로 첫 줄에서 바로 걸립니다. **시나리오를 명함 양손 전달로 바꿉니다.**

바꿀 것

- 5번 화면 손님 대사 → "명함 먼저 드리겠습니다"
- 6번 화면 제목 → "명함을 양손으로 받아보세요"
- 가이드 4줄 → 양손 전달 기준으로 다시 작성

## 3. 메뉴 구조

`취업지원 프로그램`을 **역량 강화** 허브로 바꿨습니다. 허브에서 카드로 무엇을 할지 고릅니다.

```
사이드바
  홈            /
  내 조건 진단   /self-check
  공고          /jobs
  역량 강화      /growth   ← 허브

/growth 카드
  ├ 프로그램              /programs
  ├ 문화·언어 시뮬레이션    /simulation
  └ 직무 테스트            (준비 중)
```

탭이 아니라 카드로 둔 이유는 종류가 셋이고, 각각 하는 일이 달라서입니다. 탭은 같은 것을 걸러 볼 때 쓰는 것이고, 여기는 다른 일을 고르는 자리입니다.

**직무 테스트는 아직 없습니다.** 카드는 두되 링크를 걸지 않고 `준비 중` 배지를 붙였습니다. 무엇이 준비 중인지 감추지 않습니다.

허브 안의 화면 상단에는 `← 역량 강화` 링크(`GrowthBackLink`)를 둡니다.

사이드바 활성 표시는 `NavItem.matchPaths`로 `/programs`·`/simulation`까지 함께 봅니다. 허브 안에 있어도 메뉴가 켜져 있어야 합니다.

카드 목록은 `src/lib/growth/items.ts`에 있습니다.

### 2단계 · 웹캠 검증 — **완료 2026.08.09**

`src/components/simulation/hand-mission-card.tsx` · `src/lib/simulation/hand-judge.ts` · `src/types/mediapipe.d.ts`

판정 기준은 `02_hand_test`의 값을 그대로 옮깁니다 (2.2의 코드 블록). 상수는 한곳에 모읍니다.

```ts
const WRIST_MAX_DISTANCE = 0.38;
const WRIST_Y_RANGE = [0.35, 0.95] as const;
const REQUIRED_HOLD_MS = 2000;
```

**MediaPipe는 CDN으로 로드합니다.** 세 가지를 처리해야 합니다.

1. `next/script`의 `afterInteractive`로 `hands.js` · `camera_utils.js` · `drawing_utils.js` 로드. 컴포넌트는 `dynamic(..., { ssr: false })`
2. 전역 `Hands` / `Camera` / `drawConnectors` / `HAND_CONNECTIONS`에 타입 선언 필요 → `src/types/mediapipe.d.ts`
3. **정리 코드를 다시 짜야 합니다.** 원본 `stopCam()`은 전역 변수를 쓰는데, React에서는 `useEffect` cleanup에서 `camera.stop()`과 `stream.getTracks().forEach(t => t.stop())`을 모두 불러야 합니다. 안 하면 화면을 떠나도 카메라 표시등이 켜져 있습니다.

판정은 `judgeFrame()` 순수 함수로 분리했습니다. 화면(캔버스·타이머)과 섞이면 기준을 바꿀 때 위험해집니다.

**미션 결과는 충족 아니면 확인 필요입니다. 미충족을 쓰지 않습니다.** 자세를 못 잡은 것과 할 수 없는 것은 다릅니다. 말하기 판정도 같은 규칙을 씁니다.

| 결과          | 문구                                                  |
| ------------- | ----------------------------------------------------- |
| 2초 유지 성공 | `✓ 충족` · 두 손을 모은 자세를 2초 동안 유지했어요    |
| 도중에 풀림   | `? 확인 필요` · 2초 유지 중 1.4초에서 자세가 풀렸어요 |
| 인식 안 됨    | `? 확인 필요` · 자세를 인식하지 못했어요              |

**건너뛰기를 넣었습니다** (7장 미결 항목 해소). 통과 전에는 버튼이 "건너뛰고 계속하기"로 보이고, 통과하면 "다음으로"가 됩니다. 발표장에서 인식이 안 돼도 시연이 멈추지 않습니다.

손 뼈대는 파랑(`#1F77FF`) / 회색(`#94A3B8`)으로만 그립니다. 원본의 초록·빨강은 상태 4색이라 판정 배지 전용입니다.

거부 사유 문구는 원본을 쓰되 이모지를 뺍니다.

| 상황                | 문구                           |
| ------------------- | ------------------------------ |
| 손이 안 보임        | 양손을 화면에 보여주세요       |
| 한 손만 보임        | 한 사람의 양손이 보여야 합니다 |
| 두 손이 멀리 떨어짐 | 두 손을 더 가까이 모아주세요   |
| 높이가 안 맞음      | 가슴이나 배 높이로 맞춰주세요  |

## 5. 미리 알아둘 것

**`getUserMedia`는 HTTPS 또는 localhost에서만 됩니다.** 배포는 Vercel이라 괜찮습니다. 다만 다른 기기에서 IP(`192.168.x.x`)로 접속해 시연하면 카메라가 안 켜집니다.

**CDN이라 첫 로딩이 느립니다.** `hands.js`와 모델 파일이 수 MB입니다. 3단계 진입 전에 미리 로드를 시작하는 편이 낫습니다. 오프라인 시연은 불가능합니다.

**MediaPipe 인식은 조명과 배경을 탑니다.** 발표 전에 실제 장소에서 한 번 맞춰보는 걸 권합니다. 안 될 때를 대비해 "건너뛰기"를 둘지 정해야 합니다.

**음성 인식은 브라우저를 탑니다.** 3번(말하기)과 8번(돌발 상황) 마이크는 Web Speech API로 실제 인식합니다. Chrome·Edge·Safari는 되고 **Firefox는 안 됩니다** — 지원하지 않는 브라우저에서는 마이크 대신 안내 문구가 나옵니다.

3번은 **발음을 채점하지 않습니다.** 문장에 꼭 필요한 낱말(`인사`·`안내`)이 들어갔는지만 봅니다. 발음 점수는 근거를 댈 수 없고 금지 패턴이기도 합니다 (PR-2). 낱말 칩이 말할 때마다 하나씩 채워집니다.

**인트로에 신규 기능 팝업이 뜹니다.** `src/components/intro/feature-announcement.tsx` — `/intro/*` 첫 방문 때 한 번만 열리고, `시뮬레이션 해보기` 버튼이 `/simulation`으로 보냅니다. 기기별 1회이며 `localStorage`의 `globable.announcement.simulation.v1`로 기록합니다. 다시 보려면 이 키를 지우면 됩니다.

> 옛 온보딩 팝업(`components/onboarding/onboarding-popup.tsx`)은 되살리지 않았습니다. `92%` 적합도 배지가 들어 있어 PR-2 위반입니다. 구조만 참고해 새로 만들었습니다.

**개발 안내는 두 곳에만 있습니다.** `src/components/layout/dev-notice.tsx`를 역량 강화 허브(`/growth`)와 시뮬레이션(`/simulation`) 안에 `inline`으로 넣었습니다. 전 화면 최상단 바는 뺐습니다 — 헤더 위에 있으면 잘 안 보입니다. 정식 배포 전에 두 곳에서 `<DevNotice />`만 지우면 됩니다.
